# CHAPTER 1: TEMEL KAVRAMLAR

REPOSİTORY: Yazdığınız kodları ve markdown dosyalarını bir arada tuttuğunuz github üzerindeki ana klasörünüzdür.

COMMİT: ana projeniz üzerinde belirlediğiniz ara kayıtlardır. Gruplar projeleri commitlere bölerek bu commitleri ekip üyelerine dağıtır.

BRANCH: Reponuzda açtığınız alt klasörlerdir. Kodların düzenlenmesi ve bulmanın kolay olması için takımlar sıklıkla farklı branchler açarak çalışır.

STAGE: Proje bitene kadar belirli aralıklarla repoya kaydedilen ara versiyonlardır. Bir kaza durumunda ilerleme tamamen kaybolmasın diye sıklıkla tercih edilmektedir.

MERGE: Repo içerisinde branchlerin birbirine bağlanması için kullanılan komuttur. Hedef branch içerisinde iken kaynak branch "git merge branch_adı" komutu ile hedefle bağlanır.(!!Değişikliklerin işlem öncesi kaydedilmesi gerekir. Merge komutu son kayıtlı branch i baz alır. Değişen dosyalar varsa arayüz uyarı mesajı döndürecektir.)

PULL: Farklı bir kütüphaneden reponuza dosya çekme komutudur. git pull dosya_adi ile çalışır.

PUSH: Kendi hazırladığınız dosyayı terminal üzerinden github da yayına vermeye yarar. git push dosya_adi kalıbı ile yazılır.

(!!PULL ve PUSH komutları github a özel iletişim ve dosya transfer komutlarıdır. Lokal git üzerinde çalışamazlar.)

# CHAPTER 2: TAKIMLAR NEDEN GİT VE GİTHUB KULLANIR

1) Takımlar bir proje yürütürken zaman zaman problemler ortaya çıkabilmektedir. Eğer ki projenin yedekleri daha evvelden alınmamış ise final durumunda yaşanacak ufak bir teknik aksaklık bütün sürecin en baştan başlatılmasına sebep verebilir. Takımlar bu gibi durumlar yaşamamak için özellikle büyük projelerde belirli aralıklarla commitler atar. olası bir problemde en yakın çalışan commit tekrar yüklenerek işlemlere devam edilebilir.

2) Git sistem içerisinde çalışan bir versiyon  kontrol aracıdır. Uygulama ve yazılımlarda sürüm kontrolünü ve güncellemeyi sağlar. Github ise aynı mantıkta çalışan globaldeki depodur. Github üzerinden istediğin kaynaktaki dosyayı çekip  alabilirsin. GitLab tarzı alternatifler de mevcuttur.

3) Proje için github üzerinde lider bir repo oluşturur. Ekip üyeleri ise o reponun altına kendi branch lerini açarak projenin kendilerine ait kısımlarını halledebilir. Geliştirme sonunda bütün branchler ana branch ile merge edilerek proje tamamlanır.

4) Bir takım içerisinde üyeler bazen mezun olur bazen yeni üyeler gelir ama proje bir defa o takımın reposuna kaydedilmişse ister mezun ister öğrenci olsun erişimi olan herkes o projeyi tekrar kullanabilir.

5) Otonom araç takımları bir sürü birimden oluşur. Ana kadronun proje için açtığı reponun altına kendi branch ve klasörlerini açarak yazılımlar geliştirilir. Süreç bitince bütün branchler ana branch ile merge edilir. Sistemin sürüm kontrolü ise bu ana branch üzerinden yapılır.
